# DrawAI Design

先阅读 [drawai-readme](../drawai-readme/SKILL.md)，沿用已确认的参考、页数和比例。本阶段交付确定的页面图像，实际 PPT 构建与编辑由 [drawai-image2ppt](../drawai-image2ppt/SKILL.md) 执行。

## 输入与模板

读取用户材料与当前项目，区分完成的页面图像、风格参考、内容来源与 PPTX 模板。用户已提供完整页面图像、希望忠实转换时直接检查和登记；只作风格参考的图像不能代替最终页面。

需要推荐、浏览或挑选参考时，使用现有模板页面。查询、展示和准备真实图片的操作见 [模板库](references/template-library.md)。用户已经给出模板或明确不要参考时，按其要求继续。

对于 PPTX 模板，先检查对象与渲染全部页面，识别封面、目录、章节、内容、结尾及其变体，再为每个目标页匹配实际用途。匹配规则见 [模板解析](references/template-analysis.md)。可调用 `drawai presentation inspect` 与 `render` 完成输入检查，保存原件、预览与逐页匹配记录。

## 确定每页视觉

1. 根据用户内容确定页序、每页标题、关键文字和数据。只有主题时先梳理内容并查证需要的事实；保留用户材料或可靠来源，不借用参考图里的示例事实。
2. 用户指定外接图像 API 时，使用共用连接通过 `drawai_image` 或 `drawai image generate/edit` 逐页生成；否则当前环境有图像工具时使用宿主能力。图像生成后仍由当前 Agent 制作 PPT，沿用其会话配置。每次传入该页内容、目标比例、匹配的模板截图和参考用途；每页单独生成，整套保持一致的主题，各类页面采用适合自身用途的版式。
3. 用户已经提供确定的页面图像时直接使用。有图像编辑工具且用户要求修改时按实际目标编辑。没有图像生成工具时，可用已有素材与本地 SVG／HTML／绘图代码完成真实排版并渲染为页面图像；记录采用了哪种方式。缺少所需图像或渲染能力时报告具体缺口。
4. 查看页面图像，检查文字、数字、图形、阅读顺序、留白、遮挡、比例与模板匹配。修正实际问题，再将页面图像交给转换阶段。若当前环境无法看图，说明尚未完成的视觉复核，不宣称已检查外观。

图片的用途、内容与版本由当前任务确定。明确要求直接开始时按既定要求完成视觉稿，不重复进行流程确认。需要改变用户已提供页面的内容或版式时先按其实际修改要求处理。

## 交付图像清单

在任务目录保存 `visual-spec.json`，使用实际图像路径、文字和参考记录，例如：

```json
{
  "title": "实际演示主题",
  "aspect_ratio": "16:9",
  "references": [],
  "pages": [
    {"id":"page-001","image":"visuals/page-001.png","title":"实际页面标题","content":"实际文字与数据","role":"cover"}
  ]
}
```

随后用图像转 PPT 工具登记真实文件：

```bash
drawai visual save visual-spec.json visual-deck.json
```

输出 `drawai.visual-deck.v1` 清单，保存每页实际尺寸、页序与 SHA-256。页面比例应符合已确认画布；存在差异时先完成画布适配并检查。清单写入后交给 `drawai-image2ppt`，同时保留生成提示词、使用的参考与本地排版／绘图源。
